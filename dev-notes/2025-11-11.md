# 2025-11-11 Dev Notes

## Fixed IDE Import Autocomplete

### Problem
When typing "Axon" in an IDE and selecting from autocomplete suggestions:
- Package was shown as `@node_modules/axios-fluent/dist/Axon`
- Import statement generated: `import Axon from "@node_modules/axios-fluent/dist/Axon"`
- This is poor UX - users expect: `import Axon from "axios-fluent"`

### Root Cause (Initial Understanding)
The package was exporting directly from `Axon.ts` without a proper index entry point. Modern IDEs and TypeScript use the `exports` field in package.json to determine import suggestions, and without a clean entry point, they fall back to suggesting the compiled output path.

### Root Cause (Actual - Discovered After Testing)
After testing on a separate machine, the issue persisted. The real problem was:
- `"main": "dist/index.js"` in package.json
- The `dist/` prefix in the main entry point path caused IDEs to show `@node_modules/axios-fluent/dist`
- Comparing with axios's package.json revealed they use `"main": "index.js"` (no dist/ prefix) with index files at the package root

### Solution Evolution

#### First Attempt: postbuild.js (Non-Standard)
Initially tried using a build script to generate root index files:
- Created `index.ts` with re-exports
- Used `postbuild.js` to copy and modify paths
- Excluded generated files from git
- **Problem**: This was non-standard and added unnecessary complexity

#### Research: How Do Major Packages Handle This?
Investigated popular packages to find industry standard:

| Package | Pattern |
|---------|---------|
| **axios** | Hand-written `index.js` at root, re-exports from `./lib` |
| **express** | Hand-written `index.js`: `module.exports = require('./lib/express')` |
| **jsforce** | Hand-written `index.js`: `module.exports = require('./lib').default` |
| **lodash** | Direct implementation at root |
| **TypeScript** | Published package has them (not in git) |

**Discovery**: Major single-package libraries (axios, express, jsforce) **write index.js by hand and commit it to git!**

#### Final Solution: Industry Standard Pattern (Hand-Written Re-Exports)
Switched to the pattern used by axios, express, and jsforce:

1. **Created hand-written `index.js`** (committed to git):
   ```javascript
   /**
    * axios-fluent - A fluent, type-safe HTTP client wrapper around Axios
    *
    * @license MIT
    */

   'use strict';

   module.exports = require('./dist/Axon');
   module.exports.default = require('./dist/Axon').default;
   module.exports.AxonError = require('./dist/Axon').AxonError;
   ```

2. **Created hand-written `index.d.ts`** (committed to git):
   ```typescript
   /**
    * axios-fluent - A fluent, type-safe HTTP client wrapper around Axios
    *
    * @license MIT
    */

   export { default, AxonError } from './dist/Axon';
   export { default as Axon } from './dist/Axon';
   ```

3. **Updated `package.json`**:
   ```json
   {
     "main": "index.js",           // No dist/ prefix
     "types": "index.d.ts",        // No dist/ prefix
     "exports": {
       ".": {
         "import": "./index.js",
         "require": "./index.js",
         "types": "./index.d.ts"
       }
     },
     "files": [
       "dist",
       "index.js",                  // Committed to git
       "index.d.ts",                // Committed to git
       "README.md",
       "LICENSE"
     ],
     "scripts": {
       "build": "tsc"              // Simple, no postbuild
     }
   }
   ```

4. **Updated `tsconfig.json`** - Only compile Axon.ts:
   ```json
   {
     "include": [
       "Axon.ts"                   // index.js is hand-written, not compiled
     ]
   }
   ```

5. **Updated `.gitignore`** - Removed index file exclusions (they're now committed)

6. **Deleted**:
   - `postbuild.js` - No longer needed
   - `index.ts` - Replaced with hand-written JS

7. **Reverted test/example imports** back to `../Axon` for proper coverage tracking

### Result
Now users get proper import suggestions:

```typescript
// Default export (recommended)
import Axon from "axios-fluent";

// Named export (alternative)
import { Axon } from "axios-fluent";

// With error class
import Axon, { AxonError } from "axios-fluent";
```

### Key Learnings

#### 1. Industry Standard Pattern for Single-Package Libraries
**Major packages (axios, express, jsforce) use hand-written root index files:**
- Write `index.js` and `index.d.ts` by hand
- Commit them to git (don't generate during build)
- Keep them simple - just re-export from compiled code
- No build scripts needed for this

#### 2. Why Hand-Written vs Generated?
**Advantages of hand-written:**
- ✅ Simple and explicit
- ✅ No build complexity
- ✅ Industry standard pattern
- ✅ Easy to debug and understand
- ✅ Git history tracks changes

**Problems with generated (postbuild.js):**
- ❌ Non-standard approach
- ❌ Added build complexity
- ❌ Harder to debug
- ❌ Not how major packages do it

#### 3. Package Entry Points
- The `exports` field in package.json is the modern way to define package entry points
- IDEs use `main` field to generate import suggestions
- `main: "dist/index.js"` causes IDEs to show `package/dist` in suggestions
- `main: "index.js"` (at root) shows clean package name

#### 4. TypeScript Package Structure Best Practices
1. **Hand-write root index files** for entry points (don't generate)
2. **Compile source to dist/** for implementation
3. **Keep tsconfig simple** - only compile source, not index
4. **Commit index files to git** (they're source code, not artifacts)

#### 5. Test Imports vs Package Imports
- **Tests should import directly from source** (`../Axon`) for coverage
- **Published package imports through index** (`axios-fluent`)
- The `index.js` is only for external consumers, not internal tests

#### 6. Coverage Tracking Issue
When tests imported from `../index` (re-export), coverage showed 0% for Axon.ts because v8 couldn't track through the re-export. Solution: Tests import directly from source.

#### 7. The `exports` Field
The `exports` field supports:
- `import`: For ES modules (import statements)
- `require`: For CommonJS (require statements)
- `types`: For TypeScript type definitions
- Subpath exports (e.g., `"./utils"`)
- Conditional exports based on environment

Example with subpaths:
```json
{
  "exports": {
    ".": {
      "import": "./dist/index.js",
      "types": "./dist/index.d.ts"
    },
    "./utils": {
      "import": "./dist/utils.js",
      "types": "./dist/utils.d.ts"
    }
  }
}
```

#### 8. Research Process Insights
- Don't assume - check how successful packages actually do it
- Look at multiple examples to find patterns (axios, express, jsforce)
- GitHub source code reveals the truth (not just npm package contents)
- Industry conventions exist for good reasons - follow them
